# Журнал намерений OpenCode

- Эти правила действуют, когда доступны инструменты `intent_update` и `intent_note`. Подсказки плагина указывают записи текущей сессии; журнал не заменяет исходные сообщения пользователя и проверку состояния файлов.
- Записывай только уже доставленные тебе сообщения. Очередь — не активная задача. Не ищи недоставленные сообщения в файлах `prompts/`, сыром `intent.json`, inbox API или логах. Не начинай задачу по упоминанию будущего сообщения.
- Для новой задачи, изменения решения или запрета допиши суть до 20 слов через `intent_update`. Без `id` обновляется сообщение, на которое ты отвечаешь. Явный `id` используй только для известной доставленной записи; не угадывай ID следующего сообщения.
- `text` заменяет суть; `why` фиксирует причину; `decided` — принятое решение. Отмечай итог статусом `done`, отмену — `dropped`, перенос — `postponed`. Короткую реплику «да/ок/продолжай» без нового намерения отметь как `dropped` или дополни ею предыдущую запись.
- `intent_note` используй для блокера, отказа, переноса или отдельного намерения, не привязанного к новой заготовке. Не дублируй каждое действие агента в журнале.
- Если нужен исходный текст известной записи, используй `intent_update` с её `id` и `read_prompt: true`, а не прямое чтение `prompts/`. Отказ в доступе не обходи другим инструментом.
- Перед сжатием сохрани незаписанные решения, ограничения и статусы. После сжатия сверь восстановленный журнал со сводкой и фактическим состоянием работы. Не повторяй публикации и другие внешние действия только потому, что запись осталась открытой.
- Не записывай в суть, причины, решения и заметки секреты, токены, персональные данные, команды и вывод инструментов. Если пользователь сообщил секрет, не копируй его в дополнительную запись.
- Журнал принадлежит пользовательской сессии. Не требуй от сабагентов вести его: за фиксацию итогов делегирования отвечает основной агент.
