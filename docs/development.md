# Разработка

## Проверки

Модульные тесты не используют сеть, OpenCode или платные модели:

```sh
npm test
```

Интеграционные сценарии запускают отдельный OpenCode с локальным тестовым провайдером. Основной сервис не перезапускается, платных LLM-вызовов нет. По умолчанию используется `/opt/homebrew/bin/opencode`; `OPENCODE_TEST_BIN` задаёт другой исполняемый файл.

```sh
node test/integration.mjs 0
node test/integration.mjs 300000
node test/queue.mjs queue
node test/queue.mjs steer
node test/revert.mjs
```

Сценарии оставляют временные каталоги для диагностики. Переменная `OPENCODE_TEST_TMP` задаёт родительский каталог вместо системного временного каталога.

На macOS проверен встроенный CLI Desktop 2.2.0:

```sh
export OPENCODE_TEST_BIN='/Applications/OpenCode.app/Contents/Resources/opencode-cli'
node test/integration.mjs 0
node test/integration.mjs 300000
node test/queue.mjs queue
node test/queue.mjs steer
node test/revert.mjs
node test/memory-rpc.mjs
```

`memory-rpc.mjs` проверяет настоящий HTTP RPC памяти: чтение/поиск/промпт, строгие схемы, сохранение и историю, конфликт версий, неизменность промпта, доставку уточнения в следующий запрос, запреты для дочерних сессий и чужого location, исключение откатанных уточнений и повреждённый журнал как ошибку без перезаписи.

`revert.mjs` проверяет продолжение после rewind, Undo, восстановление прежней границы и откат к первому сообщению. Эти четыре сценария проходят на 2.2.0.

### Регрессия: откат после сжатия

```sh
node test/revert.mjs after-compact
```

До исправления сценарий падал на 2.0.31 и 2.2.0: после сжатия откатываем оба новых сообщения и продолжаем сессию. Их записи оставались `open` вместо `dropped`. `ctx.session.context` возвращает только историю от последнего сжатия; по отсутствию сообщений нельзя определить точную границу отката.

Исправление сохраняет в новой записи необязательный список `reverts` из staged boundary. Прежние записи закрываются только когда новое сообщение видно модели, то есть admission и commit состоялись. Это переживает перезагрузку плагина; Undo и сбой подготовки не закрывают прежние записи. Сценарий проходит на обеих версиях.

Граница, которой нет в журнале (например, до установки плагина), пишется в `plugin.log`; новый промпт сохраняется. Для такой старой истории остаётся прежний консервативный поиск отменённых записей.

## Проектный GitHub CLI

Для работы владельца репозитория настроен `bin/gh` по образцу `gold_ops`. Нужны Ruby и установленный GitHub CLI. Скрипт перед каждым вызовом проверяет аккаунт `serge-masiutin`; глобальную авторизацию не переключает.

```sh
bin/gh api user --jq .login
bin/gh repo view --json nameWithOwner,url
```

Credentials хранятся в `gh/hosts.yml` внутри общего Git-каталога, а не в рабочем дереве. Нужны права `700` у каталога и `600` у файла. Отдельному клону требуется собственная настройка credentials; в репозитории их нет. Не используйте обычный `gh auth login/switch/logout` для проектной настройки: он может затронуть общий Keychain.

Git identity, SSH-ключ и подпись коммитов заданы локально в `.git/config`. Установке плагина эти настройки не нужны.
